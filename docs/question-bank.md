# Question Bank CMS

## Overview

The question bank provides a content management system (CMS) for PTE Academic practice questions. Administrators can create, publish, and archive questions. Students can access published questions via a read-only API.

---

## Schema

### QuestionBankItem (Prisma model)

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `id` | `String` (cuid) | Yes | Primary key |
| `taskCode` | `String` | Yes | PTE task code (e.g. RA, WE, ROP, FIBL) |
| `section` | `String` | Yes | PTE section (Speaking, Writing, Reading, Listening) |
| `title` | `String` | Yes | Short title |
| `instruction` | `String` | Yes | Task instruction text |
| `promptText` | `String` | Yes | Full question prompt |
| `promptHtml` | `String?` | No | Rich HTML version of prompt |
| `audioUrl` | `String?` | No | Audio file URL (for listening tasks) |
| `imageUrl` | `String?` | No | Image file URL (for describe image tasks) |
| `passageText` | `String?` | No | Longer reading passage |
| `optionsJson` | `String?` | No | JSON: answer options for MCQ/reorder tasks |
| `answerKeyJson` | `String?` | No | JSON: correct answers and markings |
| `sampleAnswer` | `String?` | No | Model answer or exemplar response |
| `explanation` | `String?` | No | Rationale for the answer |
| `difficulty` | `String` | Yes | easy, medium, or hard (default: medium) |
| `tagsJson` | `String?` | No | JSON: tag array for categorisation |
| `source` | `String?` | No | Origin tag (e.g. "original_sample") |
| `status` | `String` | Yes | draft, published, or archived (default: draft) |
| `createdByUserId` | `String?` | No | FK to User (set null on user delete) |
| `createdAt` | `DateTime` | Auto | Creation timestamp |
| `updatedAt` | `DateTime` | Auto | Last update timestamp |

### Statuses

| Status | Description |
|--------|-------------|
| `draft` | Work in progress, not visible to students |
| `published` | Visible to students via `/api/student/questions` |
| `archived` | Soft-deleted, not visible to anyone through normal queries |

### Indexes

- `taskCode`
- `section`
- `status`
- `difficulty`

## API Endpoints

### Admin CRUD (all require admin role)

| Method | Path | Purpose |
|--------|------|---------|
| GET | `/api/admin/question-bank` | List all items; optional filters: `taskCode`, `section`, `difficulty`, `status` |
| GET | `/api/admin/question-bank/:id` | Get single item |
| POST | `/api/admin/question-bank` | Create item (required: taskCode, section, title, instruction, promptText) |
| PATCH | `/api/admin/question-bank/:id` | Update item fields |
| PATCH | `/api/admin/question-bank/:id/status` | Update status only (publish/draft/archive) |
| DELETE | `/api/admin/question-bank/:id` | Archive (sets `status = "archived"`, never hard-deletes) |

### Student Read (requires authentication)

| Method | Path | Purpose |
|--------|------|---------|
| GET | `/api/student/questions` | Get published questions; optional filters: `taskCode`, `section`, `difficulty`, `limit`, `random` |

Student endpoint only returns items with `status = "published"`. Answer key and created-by fields are excluded from student responses.

## Seed/Import

### Development

Sample questions are automatically seeded on startup when `SEED_ON_STARTUP=true` and `isProduction=false`. The seed:
- Only inserts if the question bank is empty (no existing count check)
- Creates 4 published sample items (one per major section)
- Tags all sample items with `source = "original_sample"`
- Skips entirely in production

### Production

Production should NEVER seed questions automatically. To add questions in production:
1. Use the admin CMS UI to create items manually
2. Or connect directly to the production database and run controlled insert statements
3. Always back up the production DB before schema changes (`prisma db push`)

---

## Content Rules

All question bank content must be original. Do not use:
- Pearson official PTE questions
- Real exam questions
- Copied online question-bank content
- Copyrighted passages, audio, or images

Sample content in this project is generated by the development model (DeepSeek V4 Pro) and is clearly marked as `source = "original_sample"`.

---

## Fallback Behaviour

When the question bank has no published items for a given query:
- The student `/questions` endpoint returns an empty array `[]`
- Frontend components (PracticeEngine, MockTestEngine) fall back to existing static/local mock data
- No blank screens or fake success states are presented

---

## Schema Rollout

Schema changes are applied using `prisma db push` (not Prisma Migrate):

```bash
# Backup production DB first
cp prisma/prod.db prisma/prod.db.backup.$(date +%Y%m%d_%H%M%S)

# Apply schema
bunx prisma db push
```
